## Контекст

Идеи пользователя — `~/Desktop/pc backlog/Работа с текстом/`:
1. **Попап форматирования** на выделенном тексте (микроредактор заметки).
2. **Полноразмерный редактор заметки:** в облаке открывать по умолчанию; плавающее окно, которое
   разворачивается на папку и на всё окно; файл — в хлебных крошках.
3. **Текст на фигурах**, как в Excalidraw / FigJam: двойной клик — ввод текста внутри фигуры,
   ресайз меняет фигуру, а не шрифт.

Что есть сейчас (ветка `text-behaviour`, см. `TEXT_BLOCK_PLAN.md`):
- Заметка и текстовый блок — `.md`-файлы (текстовый блок = xattr `is_text`). Правка — сырой markdown
  в `<textarea>` (`widgets/NoteBody.vue`), просмотр — `marked` (`breaks: true`) + DOMPurify
  (`widgets/markdown.ts`). При входе в правку и выходе текст «прыгает»: `# заголовок` мелкий в
  textarea и крупный в просмотре. Форматирование — только Cmd+B / Cmd+I. Esc и Tab не обработаны,
  чекбоксы задач не кликаются, `---` под строкой текста становится заголовком, а не линией.
- Заметка сохраняется при каждом выходе из правки, даже без изменений.
- «Открыть» сводится к `open_file` (`store/createWorkspaceStore.ts`) → менеджер источника: локальный
  файл — внешняя программа (`openPath`), облачный — сырой файл в новой вкладке (`window.open`),
  хранилище браузера — скачивание, демо — ничего. В веб-меню доски пункта «Открыть» нет вовсе.
- Фигура — `.svg` (`Shape N.svg`, `viewBox 0 0 100 100`, цвет внутри SVG, `services/board/shapes.ts`),
  размер — xattr `size`, SVG растягивается под рамку. Двойной клик открывает её во внешней программе.

## Находка: CSS из чужой заметки попадает в приложение

DOMPurify в `parseNoteMarkdown` работает с настройками по умолчанию, а они пропускают тег `<style>` и
любой атрибут `style` (проверено по `dompurify@3.4.11`). Заметка в общей или публичной папке может
перекрасить или спрятать весь интерфейс у того, кто её смотрит (`<style>` после любого текста), или
накрыть экран блоком `position: fixed`. CSP в вебе — только Report-Only, на десктопе CSP нет.

**Шаг 0 (сделан):** у `parseNoteMarkdown` свой экземпляр DOMPurify — без `<style>`, `<form>` и `class`, а в
`style` только цвет, фон, выравнивание, жирность, наклон и подчёркивание (`widgets/safeInlineStyle.ts`).
Попутно: DOMPurify, которому не хватает DOM, молча возвращает HTML как есть, — теперь проверяется
`isSupported`. Тесты: `safeInlineStyle.test.ts`, `markdown.test.ts` (запасной путь),
`markdown.dom.test.ts` (настоящий DOMPurify под jsdom), ожидание в `services/ai/summarize.test.ts`;
пункт в `SECURITY.md`. Этап 1 заменит это белым списком схемы.

## Ключевые решения

### Движок — Tiptap 3 напрямую, свой UI

- Tiptap (на ProseMirror) — лучший вариант для Vue и markdown: официальный `@tiptap/markdown`
  (сейчас 3.33) разбирает `.md` на `marked` и пишет обратно в `.md`. Альтернативы хуже: Milkdown —
  markdown-first, но маленькая экосистема; Lexical и BlockNote — под React; голый ProseMirror —
  слишком низко.
- `UEditor` из Nuxt UI 4.9 — тот же Tiptap в обёртке Nuxt UI. Не берём: новый Explorer ушёл от стиля
  Nuxt UI к своему; редактор нужен в трёх местах с разной вёрсткой; а markdown там настроен без
  `breaks` — 112 из 330 демо-заметок потеряли бы переносы строк.
- Tiptap 3.27 уже лежит в `node_modules` как зависимость `@nuxt/ui`, но клиенту не виден
  (`linker = "isolated"`). Добавляем `@tiptap/*` в `apps/client/package.json` явно, одной точной
  версией. Отдельный экземпляр `marked` для Tiptap: если отдать ему общий, он перенастроит его
  (`setOptions`, `use`).
- Сырого режима нет: сырой markdown — во внешнем редакторе. `.txt` остаётся простым текстом, как
  сейчас (textarea, без попапа): форматирование ему некуда записать.

### Файл остаётся `.md`

Что пишется в файл (финально подтверждаем в прототипе 1 — под ним видно `.md`):

| Формат | В файле |
| --- | --- |
| Жирный, курсив, зачёркнутый, код, ссылка | `**…**`, `*…*`, `~~…~~`, `` `…` ``, `[…](…)` |
| Заголовки / обычный | `#`, `##`, `###` / абзац |
| Мелкий текст | `<small>…</small>` |
| Подчёркнутый | `<u>…</u>` (Tiptap 3.27 пишет `++…++`, которое `marked` не понимает) |
| Цвет текста | `<span style="color: #…">…</span>`, только цвета палитры |
| Фон (выделение) | `<mark style="background-color: #…">…</mark>`, только палитра |
| Выравнивание абзаца | `<p align="center">…</p>` (GitHub тоже понимает `align`) |
| Sub / sup | `<sub>…</sub>`, `<sup>…</sup>` |
| Цитата / блок кода | `> …` / ```` ``` ```` |
| Выноска (callout) | пишем `> [!NOTE]` (GitHub, Obsidian); читаем и `<aside>` из Notion |
| Списки / задачи | `- …`, `1. …`, `- [ ] …` |
| Разделитель | `---` (печатаешь `---` — сразу линия) |
| Перенос строки внутри абзаца | `\n`, как сейчас (Tiptap по умолчанию пишет два пробела в конце) |
| Таблицы | GFM-таблицы (без расширения таблиц Tiptap их теряет; в демо их 8 файлов) |
| Tab в тексте | табуляция; запись в начале строки подбираем в прототипе, чтобы markdown не сделал из строки блок кода |

Правила:
- **Схема редактора — белый список.** HTML внутри `.md` разбирается только правилами схемы: цвет —
  только из палитры, `<style>`, чужой `style`, `javascript:`-ссылки и скрипты не проходят.
- **Открыть и закрыть заметку не меняет файл.** Пишем, только если документ изменился (сравнение
  документа, а не строки). Иначе первое же открытие переписало бы файл, а синхронизация гоняла бы его
  по mtime.
- **Экранируем только то, без чего markdown прочтётся иначе.** Tiptap по умолчанию ставит `\` перед
  каждым `_ * [ ] ~` — `Note_1` превратился бы в `Note\_1`.
- **Неизвестное не теряется.** Конструкция, которую схема не знает, становится блоком с исходным
  текстом: показывается как есть и записывается обратно байт в байт.
- **Просмотр = та же схема.** Вне правки заметка рисуется тем же разбором (`MarkdownManager` →
  документ → HTML через `@tiptap/static-renderer`). Просмотр и правка выглядят одинаково — «скачка»
  нет. Живой редактор создаётся только у заметки, которую правят (на доске их может быть сотня).

### Палитра

~10 цветов текста и ~10 фонов, «недавние» сверху (как Notion на скриншоте). Цвета фиксированы под
светлую тему; тёмную не делаем.

### Текст фигуры — xattr и HTML-слой поверх SVG

Строка markdown в xattr `text` на файле фигуры — так же, как `title` / `description` у картинок.
Не в SVG: фигура растягивается (`preserveAspectRatio="none"`), санитайзер вырезает `foreignObject`,
SVG правят в Inkscape, а смена цвета (`apply_shape_color`) его переписывает. Xattrs уже
синхронизируются и копируются по ключам; база не меняется.

## Находки по Tiptap 3.33 (проверено в node + jsdom, 2026-11-06)

Всё ниже уже работает в прототипе П1 и переходит в этап 1:
- Подчёркнутый пишется как `<u>`. HTML внутри строки (`<u>`, `<sub>`, `<small>`, `<span style>`, `<mark>`) и HTML-блоки
  (`<p align>`) разбираются правилами схемы — неизвестный тег отбрасывается, текст остаётся.
- `<sub>` / `<sup>` без своего `renderMarkdown` при записи теряют метку — нужен свой вывод.
- `escapeMarkdownSyntax` ставит `\` перед каждым `` \ ` * _ [ ] ~ ``, а `encodeHtmlEntities` превращает `<`, `>`, `&` в
  сущности. Заменяем `editor.markdown.encodeTextForMarkdown` на скромное экранирование: `Note_1`, `a < b`, `x > 5`
  остаются как есть.
- Перенос строки по умолчанию пишется как `"  \n"` — заменяем на `\n` (`HardBreak.renderMarkdown`).
- `&#9;` в начале строки читается как табуляция: так пишем Tab в начале строки, внутри строки — обычный `\t`.
- Строка, которая начнётся с `#`, `- `, `1. `, `>` или `---`, получает `\`, чтобы не стать блоком.
- Выравнивание: абзац пишется HTML-блоком `<p align="center">…</p>` с HTML внутри. Цвет внутри него приходит из DOM
  как `rgb()` — приводим к hex.
- Выноска: свой токенизатор на `> [!NOTE]` и на `<aside>…</aside>` из Notion (иначе `<aside>` распадается на части).
- Без расширения таблиц таблица при записи исчезает целиком.
- `onReadOnlyChecked` у `TaskItem` только вызывает колбэк, документ не меняет; узел в его замыкании бывает устаревшим —
  позицию ищем по DOM чекбокса.
- `setEditable(x)` по умолчанию шлёт событие обновления — передаём `false`, иначе выход без правок переписал бы файл.

Найдено в шаге 1.1 (всё закрыто в `services/text/`, у каждого — тест):
- HTML внутри строки Tiptap разбирает как HTML: `<span style="color: …">a **b**</span>` вернулось бы с
  буквальными звёздочками. Свои токенизаторы для `<span>`, `<mark>`, `<small>`, `<sub>`, `<sup>` читают
  содержимое как markdown (у `<u>` такой уже есть). HTML-метки стоят снаружи `**`: `a**<span>b</span>**c`
  посреди слова жирным не читается.
- Свой разбор нумерованных списков в Tiptap сливает соседние списки `1.` и `1)` и оставляет пробел в начале
  строки продолжения, а его разбор пунктов теряет переносы строк в плотном пункте. Нумерованные списки читает
  marked, пункты — общий разбор пункта. Чекбокс в `1. [ ]` marked выносит в отдельный токен, Tiptap его
  выбрасывает — возвращаем текстом.
- Два соседних списка одного вида при чтении слились бы в один — у второго другой маркер (`*`, `1)`).
- Tiptap понимает по имени только `&amp; &lt; &gt; &quot;`: `&copy;` показался бы буквально. Именованные
  сущности переводим в числовые до разбора.
- Неизвестный HTML: `<!-- комментарий -->` и `<kbd>` внутри строки пропадали бы при записи — теперь узел
  `rawInline` с исходником. `<details>` с пустыми строками внутри — один сырой блок до `</details>`, иначе
  тело оказалось бы вне блока. Front matter (`---` / YAML / `---`) — сырой блок, а не линия и заголовок.
- Ссылка помнит, как написана: голый адрес, `<https://…>` или `[текст](адрес)`; голый адрес не превращается
  в `[https://…](https://…)` при первой правке. Адрес с пробелами пишется в `<…>`, `]` в тексте ссылки — с `\`.
- Картинка — строчный узел: блочная картинка Tiptap пропадала бы, если стоит в строке с текстом.
- `#### h4` при уровнях 1–3 стал бы абзацем — в схеме все шесть уровней, попап предложит три.
- У блока кода класс `language-…` из строки после ``` дал бы заметке классы приложения (`fixed inset-0`) —
  язык пишем в `data-language`. Код с ``` внутри получает забор длиннее.
- Таблица у Tiptap пишется с пустыми строками вокруг — убираем. `~` в начале текста экранировался зря
  (`lastIndexOf` с позиции −1 находит сам символ).
- Вес: `markdown.ts` со всем Tiptap, ProseMirror и marked — 738 КБ минифицировано, 227 КБ gzip (`bun build`).
  В 1.2 — отдельный чанк.
- `EditorContent` (`@tiptap/vue-3`) переносит вид редактора в страницу в `nextTick` после монтирования:
  сразу после него `editor.view.dom` уже есть, но вне страницы, и `focus()` молча не срабатывает. Пока чанк
  грузится, это не видно (фокус ждёт кадр); загруженный редактор монтируется в том же тике — курсора нет.
  `NoteRichEditor.element()` отдаёт элемент только в странице.

## Этапы интеграции

### Этап 1. Движок

Цель: заметка и текстовый блок (`.md`) правятся «как видно», без сырого markdown, и выглядят одинаково в
просмотре и в правке. Файл остаётся `.md`; открыть и закрыть заметку — файл не меняется. Попапа ещё нет
(этап 2), форматирование — горячими клавишами и markdown-вводом (`# `, `- `, `1. `, `[ ] `, `---`). `.txt`
не меняется: textarea и простой текст. Четыре шага, после каждого — тесты, `vue-tsc` и коммит в
`text-behaviour`.

- Свой счёт двойного нажатия мышью: два нажатия за 0,5 с в пределах 12 px — правка на втором отпускании (если
  оно не стало перетаскиванием). Дрожь руки от 3 px начинает перетаскивание доски, и `dblclick` браузера
  может не прийти; он по-прежнему тоже открывает правку.
- В правке — пунктирная рамка вокруг фигуры. Нажатие на фигуру вне текста фокус не уводит; в области текста
  мимо строк — курсор в конец.
- Плашка «Внутри / Рамка» дотягивается до фигуры прозрачным отступом: курсор доходит до неё, не теряя
  наведения, и её можно нажать.
- «Текст по всей рамке / внутри фигуры» в меню — с иконкой, отдельной группой под первой.
- Текст фигуры в правке не выделялся мышью (только тройным кликом — его ProseMirror делает сам): доска
  выключает выделение на виджетах (`user-select: none` и отмена `selectstart`) и включает его только заметке
  в правке. Фигура в правке получает класс `is_edit`, как заметка: выделение протягиванием и двойным кликом,
  попап; угол ресайза прячется, на холсте узел поднимается.
- Выделение, протянутое за край заметки или фигуры, отпускается на доске, и его клик был «кликом по пустой
  доске» (`@click.self`) — правка заканчивалась. Теперь клик по пустой доске или холсту — только если и
  нажатие было на пустом месте.

- **Двойной клик** по фигуре (прямоугольник, эллипс, треугольник, ромб; не линия и не стрелка —
  `isLine` уже есть в обоих шеллах) начинает правку текста вместо `open_file`
  (`PreviewWidgetContent.vue` → `useWidgetInteraction`). На таче — двойной тап, как у заметки (у фигур
  его нет). «Открыть в программе» остаётся в меню.
- **HTML-слой поверх фигуры**, текст по центру по обеим осям; ресайз меняет фигуру, шрифт тот же, текст
  переносится. Если текст не влезает, фигура растёт по высоте; ресайз не сжимает её ниже текста.
- **Область текста** (П3): по умолчанию вписанная — прямоугольник с отступом 6 %, эллипс 15 %, ромб 25 %,
  треугольник — нижняя часть (сверху 46 %, по бокам 24 %, снизу 5 %); «Рамка» — вся рамка с отступом 6 %.
  Переключатель «Внутри / Рамка» на выделенной фигуре (кроме прямоугольника) и в правом клике.
- **Цвет текста по умолчанию** — по яркости заливки: белый на тёмной, тёмный на светлой; цвета из попапа
  поверх. Выравнивание по умолчанию — по центру; «по левому краю» пишется явно (`<p align="left">`).
- **Хранение** — xattr `text` и `text_area` (только `"frame"`): `Widget.ts`, `folderContainer.ts`
  (`child_from_entry`), запись как `set_image_text` (сразу на экране, в фоне на диск, откат при ошибке).
  Пустой текст удаляет ключ. Оба ключа — в `childSignature` (`useCanvasNodes.ts`, иначе холст не увидит
  правку) и в MCP `get_folder` (`services/mcp/read.ts`). Лимит облака — 64 КБ xattrs на запись.
- **Правка не через `useNoteEditor`:** он пишет в собственный файл виджета и перезаписал бы SVG.
  Нужен вариант с чтением и записью xattr; общий слой правки (`editingNoteId`, класс `.note-widget`,
  выход по клику мимо) должен узнать и фигуру.
- Демо-заметки `piles/Features/Shapes and arrows/Note 1.md`, `Note 2.md` говорят «двойной клик
  открывает Inkscape» — после этапа устареют (решает пользователь).

## Риски

- **Нормализация при первой правке старого файла** (например, `*` → `-`). Допустимо, пока ничего
  не теряется; без правки файл не трогаем.
- **Вес:** Tiptap + ProseMirror заметно добавят к бандлу. Модуль текста грузится отдельным чанком
  вместе с первой заметкой (содержимое и так грузится асинхронно); замер — на этапе 1.
- **WKWebView (Tauri):** автозамена `--` → `—` и кавычек в contenteditable — проверить ввод `---`.
- **Тач:** системное меню выделения iOS и попап; мягкая клавиатура с contenteditable.
- **Старые версии аппа** увидят `<span style>` / `<mark>` сырыми в своей textarea.
- **AI-сводка и MCP** читают сырой `.md` с тегами — допустимо; снимать теги — потом, если надо.

## Не входит (в продуктовый бэклог)

- Слэш-меню «/», перетаскивание блоков, упоминания, картинки внутри заметки.
- Форматирование всего блока или фигуры без входа в правку (тулбар выбранного объекта, как в FigJam).
- Размер шрифта пресетами и масштаб шрифта ручкой (из `TEXT_BLOCK_PLAN.md`).
- Тёмная тема палитры.
