# Новый интерфейс: план интеграции Эксплорера

Переносим интерфейс из Vue-прототипа (`/Users/amatyukh/Desktop/pile-commander-file-manager-vue`, [репозиторий](https://github.com/a-matyukh/pile-commander-file-manager-vue)) в `apps/client`. Новый интерфейс включается флагом и работает на настоящих хранилищах с первого дня.

Статус: **черновик на ревью Cursor.** После ревью этот файл становится рабочим чек-листом, и галочки ставятся по ходу.

## Как работаем

| Кто | Роль |
| --- | --- |
| Пользователь | Владелец продукта: принимает решения, проверяет на себе, пересылает сообщения между агентами |
| Claude | Ведёт план и ревьюит каждый коммит по коду |
| Cursor | Ревьюит план, затем реализует шаги |

- **Ветка.** Вся работа идёт в одной ветке `feature/explorer`. В `main` попадает одним слиянием в конце этапа 4. Если ветка долго живёт, `main` вливается в неё, а не наоборот.
- **Шаг — это коммит.** Каждый пункт чек-листа заканчивается коммитом, который можно отревьюить отдельно. Перед коммитом нужно пройти проверки из раздела «Проверки». Пуш и слияние — только по слову пользователя.
- **Ревью.** Claude проверяет коммит по коду, а не по описанию. Замечания пишутся так, чтобы Cursor мог их выполнить без этого чата: файл, строка, что поменять.
- **Вопросы.** Если план расходится с кодом, Cursor не угадывает, а записывает вопрос в раздел «Открытые вопросы» и останавливается на этом шаге.

## Что решено

Источник решений: обсуждение прототипа с пользователем 26–27.10.2026.

### Модель для пользователя

- Пользователь видит три абстракции: **файл, папка, закладка**. Закладкой может быть любая папка с любого диска.
- Рабочих пространств, рабочих столов, окон и вкладок в интерфейсе больше нет. Вкладки заменяют закладки.
- Приложение показывает весь `~` и всё облако. Чтение ленивое, как сейчас: читается только открытая или раскрытая в дереве папка.
- Облачное рабочее пространство в интерфейсе выглядит как папка верхнего уровня в облаке. Она же остаётся единицей шаринга, публикации и Хаба.

### Внешний вид

- Дизайн, раскладку, меню и палитру берём из прототипа, а не из текущего Nuxt UI.
- Меню и диалоги собираются на «голых» примитивах Reka UI со стилями прототипа. Nuxt UI в новом интерфейсе не используется. Старые экраны работают на нём, пока их не удалят.
- Иконки — Tabler через уже существующий офлайн-плагин иконок продукта.
- Виды папок строятся на существующих реализациях продукта (`ui/workspace/folder-container/*`), а не на макетах прототипа. Из прототипа берутся только рамка вокруг вида и меню.
- Порядок видов: список, галерея, доска, холст, стопка, мозаика, слайды. Дашборда нет.
- Вид `grid` переименовывается в `gallery` (см. «Совместимость данных»). «Сетка» теперь означает только сетку привязки на фоне доски и холста.

### Поведение

- **Последнее место.** При запуске открывается папка, открытая перед выходом. Если её нет, открывается корень её диска. Историю последних папок сохраняем, но списком пока не показываем.
- **Корзина.** Локальная кнопка открывает системную корзину в Finder. Облачная корзина — страница в Эксплорере.
- **Публичные ссылки** (`/demo`, `/<user>/<slug>`, приглашения) открываются как папка только для чтения в Эксплорере.
- **Перетаскивание папки из ОС.** Брошенная на верхнюю панель папка добавляется в закладки, брошенная в любое другое место — открывается.
- **Перетаскивание в дереве** перемещает папку в другую папку. Ручная сортировка в дереве и поиск папок отложены.
- **Настройки.** Все эксперименты из настроек прототипа остаются. Пользователь сам потом решит, что убрать.
- **Веб-версия.** Вместо `~` там диск «Локальное хранилище браузера» (IndexedDB), плюс облако и Хаб.
- **Язык.** Интерфейс на русском и английском, по умолчанию язык системы. Переключатель в настройках.

## Архитектура

### Что не меняется

- `FileManager` из `packages/file-manager` — интерфейс бэкенда с реализациями `local`, `browser`, `cloud`, `demo`, `fake`. Новый интерфейс файловой системы не вводим. `FileSource` из прототипа заменяется на `FileManager` и `WorkspaceStore`.
- `WorkspaceStore` — хранилище одного корня: дерево, кэши, вотчер, `can_write`, `live`. Остаётся как есть.
- `open_workspace_store` (`store/helpers/openWorkspaceStore.ts`) — выбор `FileManager` по типу и проверка доступа. Логика не меняется, её вызывает Drive.

### Новое: Drive

Drive стоит над `WorkspaceStore` и собирает корни под одним пунктом в панели источников. Он нужен из-за облака: там один `FileManager` и один `WorkspaceStore` на каждое облачное пространство (`create_app_cloud_file_manager(workspace_id)`), а пользователь видит одно «Облако» с папками внутри.

```ts
// apps/client/src/domain/Drive.ts

/** Today's WorkspaceType; S3 or a media server becomes one more kind */
type DriveKind = 'local' | 'browser' | 'cloud' | 'demo'

type Drive = {
	/** 'local', 'browser', 'cloud'; later 's3:<bucket>' */
	id: string
	kind: DriveKind
	/** «Этот Mac», «Локальное хранилище браузера», «Облако» */
	name: string
	icon: string

	/**
	 * Top-level folders of the drive in the tree:
	 * local — one root ~, cloud — one per cloud workspace
	 */
	roots(): Promise<DriveRoot[]>

	/** The store that owns this root; opened on first use and kept */
	store_for(root_id: string): Promise<WorkspaceStore>

	/** Trash: a page in the Explorer, the system Trash (Finder), or none */
	trash: 'page' | 'system' | null
}

type DriveRoot = {
	id: string        // local: home path; cloud: workspace UUID
	name: string
	can_write: boolean
}

/** Address of any folder: bookmarks, history and the last location store this */
type FolderRef = {
	drive_id: string
	root_id: string
	folder_id: string // path inside the root, as in WorkspaceStore today
}
```

| Сейчас | Становится |
| --- | --- |
| `WorkspaceType` | `DriveKind` |
| `WorkspacesListItem` | `DriveRoot` + `FolderRef` |
| `open_workspace_store(item)` | внутренности `Drive.store_for(root_id)` |
| закладки и последние (`store/workspaces_list.ts`) | список `FolderRef` под новыми ключами хранения |

Слово «Workspace» в коде остаётся за `WorkspaceStore` и облачным пространством. В интерфейсе пользователь его не видит.

### Состояние интерфейса

Как в прототипе: модули на `reactive`, настройки в `useStorage`, без Pinia, имена в `snake_case`. Новые модули лежат рядом с существующими в `store/` под префиксом `explorer_` или в своей папке `store/explorer/`. Это решается на шаге 0.1.

## Совместимость данных

- **`grid` → `gallery`.** На файлах и в облаке лежит `user.view = "grid"`. Новый код читает `grid` как `gallery`. Что записывать, см. открытый вопрос 1.
- **Закладки и последние.** Старые списки в `localStorage` (`workspaces_list_bookmarks`, `workspaces_list_last_opened`) один раз переводятся в `FolderRef` под новыми ключами. Старые ключи не удаляются до этапа 4, чтобы выключенный флаг возвращал прежнее поведение.
- **База данных.** План не требует изменений схемы. Если они понадобятся, действуют правила из `AGENTS.md`: только прямой дифф, никакого повторного применения `schema.sql` или `rpc.sql` целиком.

## Этапы и чек-лист

Каждый пункт — один коммит. Критерий готовности указан у этапа.

### Этап 0. Фундамент

- [ ] 0.1. Флаг «Новый интерфейс» (`useStorage`, по умолчанию выключен) и пустой `ExplorerShell` вместо `WorkspaceWindow`, когда флаг включён. Переключатель флага есть и в старых настройках, и в новых.
- [ ] 0.2. `reka-ui` — прямая зависимость той версии, что уже приходит через Nuxt UI. Базовые элементы прототипа переносятся в `ui/kit/`: меню, кнопка-иконка, сегментный переключатель, тултипы, модалка.
- [ ] 0.3. Палитра и токены прототипа, шрифт и сглаживание. Стили не протекают в старый интерфейс.
- [ ] 0.4. i18n: `t()`, словари `ru`/`en` с проверкой одинаковых ключей типами, язык системы по умолчанию.
- [ ] 0.5. `Drive` для `local` (корень `~`), `browser` и `cloud` поверх `open_workspace_store`. Тесты на `fake`.
- [ ] 0.6. Навигация: текущее место (`FolderRef` или страница), история назад/вперёд, восстановление выделения при возврате, последнее место при запуске.
- [ ] 0.7. Закладки на `FolderRef` и перенос старых закладок.

Готово, когда: с включённым флагом приложение запускается в пустую рамку, открывает последнюю папку, а в консоли видно дерево `~` и облака через Drive. С выключенным флагом всё работает как раньше.

### Этап 1. Верхняя панель

- [ ] 1.1. Назад, вперёд, кнопка сайдбара и горячие клавиши ⌘←, ⌘→, ⌘B. Отступ под светофор macOS и область перетаскивания окна (`data-tauri-drag-region`, см. `WorkspaceWindow.vue`).
- [ ] 1.2. Панель закладок и выпадающий список закладок.
- [ ] 1.3. Перетаскивание папки из ОС: на верхнюю панель — закладка, в остальное окно — открыть. Точку броска даёт Tauri, логика сейчас в `AppShell.vue` (`listenFolderDrop`).

Готово, когда: по закладкам и истории можно ходить по реальным папкам, а содержимое показывается старым видом папки.

### Этап 2. Сайдбар

- [ ] 2.1. Панель источников (диски, Хаб) и изменение ширины сайдбара.
- [ ] 2.2. Дерево на `WorkspaceStore.tree`: ленивое раскрытие, скрытые файлы, меню папки.
- [ ] 2.3. Панель фильтров и сортировки дерева.
- [ ] 2.4. Перетаскивание в дереве = перемещение папки.

Готово, когда: по всему `~` и облаку можно ходить только деревом.

### Этап 3. Эксплорер

- [ ] 3.1. Шапка папки: хлебные крошки, подзаголовок, действия с папкой, выбор вида.
- [ ] 3.2. Страницы: настройки (интерфейс, ИИ, другое), аккаунт, Хаб, облачная корзина. Логика берётся из существующих диалогов (`AccountPanel`, `AuthForm`, `ProfileDialog`, `PasswordDialog`, `AiSettingsSection`), меняется только оболочка.
- [ ] 3.3. Рамка вокруг существующих видов и горячие клавиши навигации по элементам (стрелки, ⌘↑, ⌘↓).
- [ ] 3.4–3.10. Виды по одному коммиту: список, галерея, доска, холст, стопка, мозаика, слайды.
- [ ] 3.11. Публичные ссылки и демо как папка только для чтения.
- [ ] 3.12. Синхронизация, шаринг, публикация и диалоги вокруг облачной папки верхнего уровня.

Готово, когда: всё, что умеет старый интерфейс, доступно в новом.

## Открытые вопросы

1. **Что записывать вместо `grid`.** Установленные версии 2.2.x и участники облачных папок на старых версиях не поймут `gallery`. Предложение Claude: до этапа 4 читать оба значения и записывать `grid`, а `gallery` начать записывать после того, как старые версии обновятся.
2. **Где живёт состояние нового интерфейса:** `store/explorer/` или файлы с префиксом в `store/`. Решается на шаге 0.1.
